# Agent Note：侧栏应用启动与内嵌面板

Status: implemented

[English](2026-09-18-sidebar-application-launch.md) | 中文

## 问题

部署里反复出现的开局动作常常是「把那个工具跑起来」：工作室自己的 dev server、某个设计器、某个地图编辑器。[quick-start 座位](2026-09-16-sidebar-quick-start-actions.zh.md) 只能新建一个携带指令的会话，用户仍然要手动把工具起起来——找到并双击 `start.bat`、等它的服务就绪、打开它的页面——之后才能开始那条指令所描述的工作。启动工作的页面和真正干活的页面留在两个窗口里，而 harness 对工具的状态一无所知。

## 决定

开工动作成为一个封闭的二元联合，由 node 半部在解析配置时打上标签：`{ kind: 'prompt', id, label, prompt }` 与 `{ kind: 'app', id, label, command, url }`。每一项由它携带的字段表明自己的形态；`resolveActions` 拒绝同时表明两种形态或一种都不表明的项，两个半部都按标签分派，而不是各自重新推导形态。

application 按下把该动作的 `id` POST 到 `/api/quickstart.launch`——Connection 共享 `/api` 通道上的一条 Fetch 路由。它不是 `webServer` 路由，因为桌面端宿主只把 `/api/*` 请求转发给宿主进程：`webServer` 路由会在 Web 面应答，而在桌面应用里返回 405。命令不跨线；请求只报出动作名，命令始终是部署自己的配置。

node 半部以分离方式启动已配置命令，不接任何 stdio 管道，因此应用比 dsh 活得更久。Windows 上经由 `cmd.exe /c start "" <command>`，这让配置的脚本得到与双击相同的控制台窗口并立即返回；其他平台由 `sh` 把脚本路径当作单个 argv 项接收，没有 shell 重新解析它。就绪以页面应答为准：先探测 `url`——有应答说明应用已在运行，于是不启动任何东西——启动之后再反复探测，直到 `launchReadyMs` 用尽。命令若是绝对路径，会在运行前确认它确实是一个文件，因此过期配置会让这次按下立刻失败，而不是等到时限。

浏览器半部为每个 application 动作注册一条键为 `quickstart-app:<id>` 的 `main` 键控面板，外加一条选中它的 `sidebar.panellist` 行。所有面板注册共用一个按动作 id 键控的 store 实例，因此应用状态在中栏被切走又切回后仍然保留，并由唯一一个 launcher 写入。面板在状态为 ready 后把 `url` 嵌进 iframe；重新加载会递增 revision 并以重挂载 frame 实现，因为这是重载一个 harness 无法触及的跨源文档的唯一手段。

## 考虑过的备选方案

**在浏览器窗口里打开页面。** 桌面端外壳拒绝 `window.open`，也拒绝离开自身协议的导航，因此在桌面应用里，页面只能经由宿主侧原生打开器离开 harness 窗口；而部署本身的要求就是在一个窗口里干活。浏览器标签页也在面板控件之外，它的重新加载与返回手势将无处安放。

**用 `shell.overlay` 承载页面。** 整帧浮层是徽标、提示与状态胶囊这类内容的加法座位：默认点击穿透，没有分栏几何，也没有导航行。一个完整应用属于中栏，而中栏本来就拥有面板选择以及选中它的那些侧栏行。

**做成右侧栏 dock 标签页。** 该子系统的标签页是按会话作用域的，其种类由它自己的契约定义；一个在每个会话都可用的部署工具将不得不为一个不读会话的页面伪造一个会话作用域标签页。

**做成 `webServer` 路由。** 这是宿主能力最自然的家，但在桌面应用里不可达。Connection 的共享通道是两个面都承载的唯一传输，它的物理承载方为该通道上每条路由负责 Host/Origin 围栏与浏览器鉴权。

**通过 `ctx.subprocess` 启动。** 受管子进程能力拥有一个进程范围并在拆除时终结它，那会连同 dsh 一起结束用户的工具服务；它的请求模型也没有分离模式。被启动的应用必须比 harness 活得更久。

**用 `scrubbedParentEnv` 清洗子进程环境。** 那个辅助函数正好合适，但它不在依赖策略已分类的宿主导出里，而该名单禁止自动化 agent 添加条目。因此子进程继承环境；包 README 记录了该缺口以及它留下的信任边界。

**让浏览器轮询 URL。** 从 harness 文档发出的跨源探测需要 CORS 或 `no-cors` 语义，并且只能报告单个浏览器观察到的结果。宿主本来就与页面同机运行，可以在不让页面为每次尝试各持一个请求的情况下等待。

**把命令当作 shell 字符串执行。** 可表达参数，代价是在 shell 里重新解析一条配置路径。命令是程序或脚本路径，各平台适配器各自构建 argv。

## 后果

application 动作会为配置它的组合新增一项宿主能力：该路由只在至少配置了一个 application 动作时存在，而时限（`launchReadyMs`，默认 120000）限定等待，但不会终结应用。

按下对正在运行的应用是幂等的，但对另一个 harness 进程不是：宿主按动作 id 合并尝试，浏览器也合并按下，而没有任何共享记录写着「正在启动」。

按下不依赖会话、工作区或模型回合；面板是一条根作用域的键控条目，渲染自己动作的状态，部署的页面来自配置而不是会话数据。

组件、注册、launcher、路由与启动过程的 spec 覆盖两种动作形态、各拒绝分支、状态机、就绪探测、三种失败原因、共享尝试以及合并的按下；它们位于 [`packages/client/ui-quick-start/tests`](../../../../packages/client/ui-quick-start/tests)。
