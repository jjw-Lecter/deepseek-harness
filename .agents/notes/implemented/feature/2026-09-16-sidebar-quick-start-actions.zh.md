# Agent Note: Sidebar quick-start actions

Status: implemented

[English](2026-09-16-sidebar-quick-start-actions.md) | 中文

## 问题

每次开始同一类工作，都要重打同一段话。侧栏的「新建会话」按钮只打开一个会话，对这个会话是为什么开的只字不提；因此当某个部署的用户总是从少数几条固定请求之一开始时——某条项目流程、某个工作室角色、某类领域任务——这个部署没有办法给它们命名。用户重打一遍请求，而重打出来的措辞并不是该部署想要的请求。

## 决策

`sidebar.quickstart` 是侧栏外壳中的 single root 作用域洞，紧贴「新建会话」下方、全局面板行上方渲染。外壳只把栏状态（`wide`）交给占位者，别无其他：按下按钮做什么属于注册者的事务。

[`@deepseek-ai/dsh-client-ui-quick-start`](../../../../packages/client/ui-quick-start/README.zh.md) 用配置的 `actions` 列表填充它，列表项有两种形态，由 node 半部在解析配置时打上标签。**prompt** 项 `{ id, label, prompt }` 在按下后打开一个会话，并通过 `ctx.conversation.input.for(actx).setDraft` 把 `prompt` 写入该会话的输入框；不会发送，因此指令始终可编辑，花掉请求的是用户按下的回车。**application** 项 `{ id, label, command, url }` 启动本宿主持有的一个程序，并打开嵌入其页面的面板，这由 [application-launch 笔记](2026-09-18-sidebar-application-launch.zh.md) 记录。

本包同时具有两个面，因为 `dsh.client` 行的 `config` 只到达它的 node 半部：浏览器启动从 boot manifest（`WebBootEntry`）组合插件行，而该 manifest 不携带 `config`，`bootClient` 调用的是 `loader.create({ name })`。node 半部解析配置，并向 Web 服务端与桌面端宿主都会渲染的索引注入表推入一条 `global` 行；浏览器半部读取该全局量。[`dsh-client-connection`](../../../../packages/client/connection/README.zh.md) 也以同样的注入传递它的恢复时序。

由哪个会话接收它，遵循「新建会话」流程。当前会话本来就是空白会话时由它直接接收，因为另起一个只会重新打开同一个会话。否则按下会记下指令，再由 `ctx.uiWorkspace.startSession()` 打开工作区流程产出的会话；会话列表订阅在那个会话成为当前会话时投递指令。这份记录写明了按下时所在的会话，因此连接过程在会话到达前发布的列表变化花不掉它；而另一个已经带对话内容的当前会话会结束这次启动，而不是接收这段文本。

加载会拒绝无法渲染、无法区分或无法启动的 `actions` 列表——空的 `id` 或 `label`、同时表明两种形态或一种都不表明的项、所表明形态里的空字段、不是绝对 http(s) URL 的 `url`，或重复的 `id`——因为这些失败在浏览器里都没有更晚的解决点，那里没有可以回指的配置。空列表不是失败：座位不渲染任何内容。

`dsh-web-app` 为本部署的魔兽争霸 3 RPG 工作室配置了四个动作：开发、UI 设计与数值平衡，各自以把工作路由到 `C:\Users\10639\.agents\skills\gamestart` 的指令开场；外加工作室自己的工作台，它启动 `D:\AiWAR3WorkFlow\start.bat` 并嵌入其页面。

## 考虑过的替代方案

**按角色使用 Agent 预设。** 预设组合的是 agent 运行时所带的东西——工具、提示词分节——并且在它创建的会话上固定下来。这些入口的差别在于用户请求什么，而不在于会话被允许做什么；把它们表达成预设会增加行为相同的多个组合，并与已经拥有组合选择权的预设面竞争。

**把按钮放进输入框自己的动作行。** 输入框持有这条指令将要替换的草稿，因此控件会紧挨它所编辑的对象。但它不会落在开始工作的那个界面上：首屏输入框只是其中一个界面，而侧栏在所有界面上都存在。

**把按钮硬编码进随附外壳。** 把某个部署的领域文案写进客户端源码，等于让产品本身承载一份配置。本包持有机制，部署的行持有这些动作，因此另一个部署无需改动源码即可替换它们。

**在浏览器半部读取行配置。** 这个选项看起来最自然，`dsh.client` 行的 `Config` 声明也在暗示它。但它行不通：组合浏览器行的 boot manifest 不携带配置，这样的行永远只跑 schema 默认值。只有 node 半部能看到部署配置了什么，这正是动作集经由索引注入表过界的原因。

**部署专属的预设或提示词文件。** 预设组合的是 agent，而不是给请求命名；让本包在运行时读取某个文件，则会把部署数据放到本包并无契约的路径之后。

**按下即发送指令。** 按下就立刻花掉一次请求并开始改文件，既不留出可以更正指令的时点，也让一次误点变得昂贵。

## 影响

这些动作经由 `dsh-web-app` bundle patch 同时到达桌面端与 `dsh web`，因此本部署的领域文案位于部署自己的组合层，而不是某个包里。另一个部署覆盖该行的 config 即可。

动作的 `label` 属于配置，因此不做本地化；同一个字符串服务所有界面语言。折叠栏显示标签的第一个字符，因为折叠栏放不下文本，而配置里不带图标。

prompt 按下会替换空白会话的整份草稿，因此该空白会话里已经输入的文字会丢失。本座位的用途就是让会话以它的指令开局，而把两个开场合并会留下含义不明的第一条消息。

当该部署没有任何工作区时，侧栏的「新建会话」会清空到无会话视图，prompt 按下也就没有可打开的会话。当时有当前会话时，启动到此结束；当时没有当前会话时，指令会等到下一个空白会话成为当前会话。application 按下完全不依赖会话。

组件与控制器规格覆盖了两条分支、暂存的消费与放弃路径、加载时的拒绝、折叠栏形态，以及 application 形态的面板与启动路径；`ui-sidebar` 的规格与 DOM 快照承载了这个新洞。
