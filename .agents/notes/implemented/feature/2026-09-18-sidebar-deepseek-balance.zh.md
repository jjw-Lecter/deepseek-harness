# Agent Note：侧边栏 DeepSeek 余额

Status: implemented

[English](2026-09-18-sidebar-deepseek-balance.md) | 中文

## 问题

会话消耗账户额度，而 harness 从不说明还剩多少。这个数字本来存在——`GET /user/balance` 会针对部署已经配置好的凭据作答——但它待在另一个窗口里，于是用户是从一次失败的请求、而不是在请求之前得知余额已经用完。

## 决定

侧边栏的品牌行新增一个状态席位 `sidebar.brand.status`：一个 root 作用域的列表，渲染在品牌组与栏折叠按钮之间、New Session 按钮的点击区域之外。它只存在于展开的栏中；56px 轨道放不下状态单元，而读不到的数字不值得占用一个控件。

[`@deepseek-ai/dsh-client-ui-deepseek-balance`](../../../../packages/client/ui-deepseek-balance/README.zh.md) 用它填充 DeepSeek 账户余额。本包同时具有两个面。它的 node 半部在 Connection 共享的 `/api` 通道上注册一条精确 Fetch 路由 `GET /api/deepseek.balance`，浏览器半部注册一个按 60 秒节奏并在每次按下时读取该路由的单元。

这条路由位于共享通道而不是 `webServer`，理由与启动路由相同：桌面端宿主只把 `/api` 请求转发给宿主进程，因此裸 `webServer` 路由会只在一个面存在、在另一个面返回 405。载体为该通道负责信任与鉴权，而请求本身不带任何参数——凭据引用与端点始终是部署自己的配置，绝不是浏览器提供的值。

宿主声明凭据 seam，并在每次读取时通过 `ctx.credentials.resolve` 解析一次 Key，针对的是 Models 页面写入、DeepSeek 提供方解析的同一个引用，因此启动后存入的 Key 就是余额所反映的那个 Key。没有挂载凭据提供方的组合永远不会激活这一行。所配置的引用按凭据 seam 接受的环境变量语法校验，因为该 seam 自身的构造函数对 `packages/client` 包而言不是已分类的宿主导出，而依赖策略禁止自动化 agent 添加条目；`dsh-api-settings-controller` 也为自己的输入字段声明了同一套语法。

服务商读取携带完整的失败分类：`not-configured`、`unauthorized`、`timeout`、`unreachable` 与 `invalid-response`。浏览器把每个判别值本地化成自己的文案，并原样显示宿主给出的细节行。

金额保持服务商给出的十进制字符串。本包只负责显示它们，因此把它们解析成二进制浮点数只会引入漂移。读取失败时在错误标记下保留上次成功的金额：用户正盯着这个数字，清空它隐藏的信息多于它保护的东西——提示气泡承载失败原因与金额的时间。

服务商主体与浏览器收到的应答都经过校验。服务商是外部服务，宿主是另一个进程，因此缺少标志位、列表不是数组、条目没有给出金额、应答被截断、或宿主由另一版本构建，都只会得不到余额，而不是得到零余额。

## 考虑过的备选方案

**放在会话作用域的标题栏里。** 余额是没有任何会话拥有的账户事实；共用一个 Key 的两个会话会各自渲染同一个数字，而没有请求在途的会话也照样显示它。侧边栏列在任何会话存在之前就已存在，账户事实正属于那里。

**在浏览器半部读取余额。** Key 位于宿主进程内；为了直接访问服务商而把它放进页面，等于把凭据交给每位页面访问者，而且桌面端根本到不了内部端点。

**用 `webServer` 路由。** 上文已否决：它会在 Web 面可用，而在桌面端失效。

**可配置的刷新节奏。** `dsh.client` 行的 `config` 只到达 node 半部，因此由浏览器持有的节奏需要再开一条索引注入通道来传递一个数字。该间隔是一个单元的产品节奏；真正随部署变化的事实——凭据引用、端点、截止时间——才是配置。

**只在请求进行中显示金额。** 这个单元回答的是「我现在能不能开工」，而这个问题在任何会话存在之前就会被问。

**像提供方那样读取 `$DEEPSEEK_BASE_URL` 与环境。** `dsh-launch-environment` 的导出在依赖策略的宿主导出名单中未分类，而该策略禁止自动化 agent 添加条目，因此这一行自己声明端点并要求凭据 seam。代价写在包 README 里：网关部署要把同一个根地址写两遍，一遍给提供方路由，一遍给这里。

**不设按下、仅自动刷新。** 按下让数字在用户读取它的那一刻可信，代价是一次很小的鉴权 GET。

## 后果

`dsh-web-app` 挂载了该行，因此 `dsh web` 与桌面端宿主都会显示这个单元；部署在自己的行上覆盖 `apiKeyEnv`、`baseURL` 或 `timeoutMs`。凭据未配置时该单元报告配置缺失而不是让加载失败，因此没有 DeepSeek Key 的部署照常启动，只是显示一个带标记的占位符。

外壳改动是加法式的：`sidebar.brand.status` 是一个新的 `list` 席位，因此 `ui-brand-official` 的占位者与所有既有注册都不受影响，空席位不渲染任何内容。

读取失败会留下带错误标记的陈旧金额，这是包 README 记录的刻意取舍：另一种做法是清空该单元，从而隐藏用户正在关注的数字。

`balance.host.spec.ts` 针对本地服务器覆盖服务商读取，`route.host.spec.ts` 在回环服务商之上挂载真实插件，客户端规格覆盖解码、控制器的节奏、合并、卸载与保留的读数、单元的各种状态及其注册；`ui-sidebar` 的规格与 DOM 快照承载新席位。
